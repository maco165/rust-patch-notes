ルーレットに必勝パターンはあるのか

Bandit Camp のルーレットにまつわる 7 つの話を、サーバーの処理を読んだ結果から 1 つずつ確かめます。結論は、パターンはありません。

結論

パターンはありません

当たりのマスは、回し始めの瞬間に 25 マスから等しい確率で 1 つ選ばれます。前の結果も、時刻も、賭けた人や額も使われません。

  • 1/25どのマスも同じ確率
  • −4%1・3・5 に賭けたときの平均の戻り
  • −16%20 に賭けたときの平均の戻り

どの数字に賭けても、続けるほど減ります。損をいちばん小さくするなら 1 です。

この記事では、ルーレットのマスを、ゲームの中の表示と同じ 1・3・5・10・20 の数字で呼びます。数字は当たったときの倍率です。

ルーレットはこう動いている

1 回の流れ

  1. 賭けの受け付け45 秒スクラップを置けるのはこの間だけ
  2. 回し始め一瞬当たりが決まり、同時に賭けを締め切る
  3. 回転13〜18 秒 + 減速決まったマスへ向かって回るだけ
  4. 配当一瞬当たりは戻り、外れは消える

当たりが決まるのは、輪が回り始める前です。回っている間は、もう結果は変わりません。

当たりを決めるときに使うもの、使わないもの

使うもの

  • マスの数 (25)
  • その場で作り直した乱数

使わないもの

  • 前の回の結果
  • 時刻、回の番号
  • サーバーの人数
  • 賭けた額
  • 賭けた人
  • 輪の回り方

回し始めの処理を、言葉で書くとこうなります。

回し始めるとき:
  新しい種を 1 つ作り、その種で乱数を作り直す
  当たりのマス = 0 番から 24 番のうち、等しい確率で 1 つ
  止まる角度と、回る時間の長さを決める
  賭けを締め切る

実際のコードが呼んでいる乱数

回し始めの処理は、乱数を次の順に呼んでいます。どれも Unity と .NET に元からあるメソッドで、Rust が独自に作った乱数ではありません。

順呼んでいるメソッド何を決めるか
1UnityEngine.Random.Range(int.MinValue, int.MaxValue)種。Unity の乱数から整数を 1 つ取る
2new System.Random(種)その種で、.NET の乱数を新しく作る
3Next(0, マスの数)当たりのマス。0 以上 25 未満の整数、つまり 0〜24
4NextDouble()止まる角度のずれ (±6 度)。0 以上 1 未満の小数から作る
5NextDouble()回る時間の長さ (13〜18 秒)

それぞれの性質は、公式の文書に書かれています。

  • UnityEngine.Random は Xorshift 128 という方式で、状態はゲーム全体で 1 つを共有します。サーバーの中のほかの処理も同じ乱数を使うので、ルーレットが種を取る時点の状態は、ほかの処理がそれまでに何回呼んだかで変わります。
  • System.Random(種) は、同じ種からは同じ数の並びを作ります。ルーレットは回すたびに新しい種で作り直すので、前の回の並びの続きにはなりません。
  • Next(最小, 最大) は、最小を含み、最大を含みません。Next(0, 25) が返すのは 0〜24 で、25 マスのどれかがそのまま選ばれます。
  • NextDouble() は 0 以上 1 未満の小数を返します。角度のずれと回る時間に使われるだけで、当たりのマスには関わりません。

当たりのマスを決めているのは 3 番の 1 行だけです。その前後に、前の結果や賭けの中身を混ぜる処理はありません。

25 マスの並び

1 は 1 つおきに入り、20 は 1 マスだけです。調べた 7 台は、すべて同じ並びでした。

数字ごとの当たる確率

  1. 1 (12 マス)48%
  2. 3 (6 マス)24%
  3. 5 (4 マス)16%
  4. 10 (2 マス)8%
  5. 20 (1 マス)4%

当たりやすさを決めるのは、その数字のマスの数だけです。

同じ動きをするプログラム

読んで分かった動きを、自分で一から書いたプログラムです。ゲームのコードは写していません。当たりを決める部分と、配当の部分はこれだけです。

import random

# 25 マスの並び。数字は当たったときの倍率
SEGMENTS = [3, 1, 10, 1, 3, 1, 5, 1, 5, 3, 1, 10, 1, 3, 1, 5, 1, 3, 1, 20, 1, 3, 1, 5, 1]

def spin(source):
    """1 回分。新しい種で乱数を作り直し、25 マスから等しい確率で 1 つ選ぶ"""
    fresh = random.Random(source.getrandbits(32))
    return fresh.randrange(len(SEGMENTS))

def payout(bets, segment):
    """bets は {数字: 賭けた額}。当たった数字の賭けだけが (1 + 数字) 倍で戻る"""
    number = SEGMENTS[segment]
    return bets.get(number, 0) * (1 + number)

上の表との対応は、source.getrandbits(32) が 1 番 (種を取る)、random.Random(...) が 2 番 (乱数を作り直す)、randrange(25) が 3 番 (マスを選ぶ) です。乱数の方式は Python のものなので、出る数の並びはゲームと同じにはなりませんが、選び方は同じです。

spin の中に、前の回の結果・時刻・賭けの中身を受け取る場所がありません。入ってくるのは乱数のもとだけです。パターンが生まれる余地が無いことが、形からも分かります。

よく聞く話を確かめる

「しばらく 20 が出ていないから、そろそろ 20 が来る」

成り立たない前の回の結果は、どこにも使われていません。乱数も回すたびに作り直されます。20 が 100 回出ていなくても、次に 20 が出る確率は 4% のままです。

「輪の回り方を見れば、止まる場所が読める」

読めても賭けられない止まる場所は回し始めの時点で決まっていて、その時点で賭けは締め切られています。途中の速さや減速の入り方は、結果を変えません。

「時間帯や、サーバーの人数で出やすい数字が変わる」

変わらない当たりを決める処理が使うのは、マスの数 (25) だけです。時刻も、プレイヤーの数も入っていません。

「大きく賭けると外れやすい」

関係ない当たりを決める処理は、賭けた額も、誰が賭けたかも見ていません。賭けの中身が読まれるのは、当たりが決まった後の配当のときだけです。

「20 の隣は出やすい。マスの並びに意味がある」

関係ない当たりは「マスの番号」で選ばれ、どの番号も 1/25 です。並びは当たりやすさに関係しません。

「外れたら倍にして賭け直せば、最後は勝てる」

平均の戻りは変わらない毎回の結果が前の結果と関係しないので、賭ける額の順序を変えても平均の戻りは同じです。外れが続くと賭け金だけが急に増えます。1 でも、10 回続けて外れることが 1,000 回に 1 回ほど起きます。

「全部の数字に賭ければ負けない」

必ず当たるが、平均で減る5 つの数字に 1 ずつ賭けると、5 賭けて平均 4.6 が戻ります (−8%)。当たった数字以外の賭けは、その回で消えるからです。

それでも偏って見える理由

  • 36%25 回続けて 20 が出ない確率
  • 2.5%1 が 5 回続く確率 (40 回に 1 回ほど)

確率どおりでも、結果は偏って見えます。3 回に 1 回は「25 回回しても 20 が来ない」のが、確率どおりの姿です。人は連続や偏りに理由を探しますが、ここでは理由はありません。

分からないこと

  • 2024 年 5 月より前。 2024-05-02 のアップデートで、公式が「Bandit Camp のルーレットの乱数の扱いを作り直した」と書いています。それより前の作りにパターンがあったかどうかは、公開されている資料からは分かりません。今後、当時の版のソースを読んで調べる予定です。
  • 種を外から当てられるか。 種はサーバーの中の乱数から作られ、プレイヤーには送られていません。外から当てることはできないと見ていますが、これは推定です。
  • この記事の対象。 2026-11-07 の版の PC 版のサーバーです。今後のアップデートで変わることがあります。

調べ方

サーバー本体の処理 (ルーレットのクラスの中間コード) を読み、ルーレットと端末の設定の値をデータのファイルから読みました。サーバーは起動していません。倍率 (1・3・5・10・20)、マスの数、受け付けの 45 秒、回る時間の 13〜18 秒は、どれも読んだ値です。確率と平均の戻りは、そこから計算したものです。

ゲームの中で実際に回して数えた結果ではありません。処理がそう書かれている、という確認です。記事の中の 10 万回の結果は、同じ動きをする自作のプログラムを回したものです。
