ブラックジャックとポーカーは、数えれば勝てるのか

ブラックジャックの台とカードテーブルを、サーバーの処理を読んだ結果から確かめます。山札は毎回作り直され、カードを数えても有利になりません。店の取り分は約 0.8% です。

結論

カードを数えても、有利になりません

山札は、回が始まるたびに新しく作って切り直されます。ブラックジャックは 10 組 520 枚、ポーカーは 1 組 52 枚。前の回に出た札は、次の回に何も残しません。

  • 520 枚ブラックジャックの山札。毎回作り直す
  • 約 −0.8%ブラックジャックを基本戦略で打ったときの平均 (概算)
  • 0ポーカーで店が取る分。全額がプレイヤーに戻る

ブラックジャックは、決まりどおりに打てば、ルーレット (いちばん良い賭け方で −4%) よりずっと減りにくい遊びです。それでも平均では減ります。ポーカーは店の取り分が無く、損得は相手との勝ち負けだけで決まります。

この記事では、Bandit Camp などにあるブラックジャックの台 (クラス名は BlackjackMachine) と、カードテーブル (CardTable。遊べるのはテキサスホールデム) を扱います。

ブラックジャックはこう動いている

1 回の流れ

  1. 山札を作る一瞬10 組 520 枚を新しく並べて切る。賭けより前
  2. 賭けの受け付け最長 30 秒5〜500 スクラップ
  3. 配る1 秒席の番号の順に 2 枚ずつ。ディーラーは 1 枚伏せる
  4. 自分の番操作ごとに 30 秒全員が同時に進める
  5. ディーラーの番1 秒に 1 枚合計だけで機械的に引く
  6. 配当1 秒後4 秒後に次の回

山札が作られるのは、賭けを受け付ける前です。賭けた額を見てから札を並べる処理はありません。

2.5 倍は端数を切り捨てます。5 を賭けると 12.5 ではなく 12 が戻るので、賭け金は偶数にしておくと損がありません。

札を決めるときに使うもの、使わないもの

使うもの

  • その回のために新しく並べた山札
  • 暗号用の乱数 (札を切るときだけ)
  • 札の合計 (ディーラーが引くかどうか)

使わないもの

  • 前の回の札と結果
  • 時刻、回の数
  • サーバーの人数
  • 賭けた額
  • 賭けた人、勝ち負けの履歴
  • 台がそれまでに払った額

賭けたスクラップは回の終わりに消え、戻りは新しく作られます。台は「貯まった分」を持っていないので、「そろそろ吐き出す」という状態がそもそもありません。

山札の切り方

札を切る処理が呼んでいる乱数は、.NET に元からある System.Security.Cryptography.RandomNumberGenerator.GetInt32 だけです。OS の暗号用の乱数で、種も、ゲームの中の状態も持ちません。ルーレットが使う Unity の乱数とは別のものです。

切り方を言葉で書くと、こうなります。

新しい山札を作るとき:
  スペードの 2 から クラブの A まで、組の数だけ順に並べる
  山のいちばん上の位置から順に、下へ向かって:
    その位置より「下」のどこか 1 か所を等しい確率で選び、札を入れ替える
札を配るとき:
  いちばん上から 1 枚ずつ取る

1 枚ぶんだけ、均等からずれている

教科書の切り方 (Fisher–Yates) は、入れ替える相手に「その位置自身」も含めます。札がたまたま動かないことも、起きてよいからです。この台の切り方は、相手を「その位置より下」からしか選びません。Sattolo の方式と呼ばれる形で、どの札も、切る前に自分がいた位置には絶対に残りません。

新品の山の上から 13 枚は、切る前はこの並びです (すべてクラブ)。

AKQJ1098765432

切ったあと、いちばん上に来る札は「もといちばん上にあったクラブの A」以外の全部から等しく選ばれます。2 番めは「もと 2 番めにあったクラブの K」以外から、と続きます。つまり、最初に配られる 1 枚は、あのクラブの A にだけはなりません。

山札最初の 1 枚が A である確率均等に切った場合
ブラックジャック (520 枚)39/519 = 7.51%40/520 = 7.69%
ポーカー (52 枚)3/51 = 5.88%4/52 = 7.69%

ずれは 1 枚ぶんです。ブラックジャックの店の取り分を 0.1 ポイントほど増やす、と計算しました (あとの節)。回をまたいで偏りが積み重なることはありません。山札は毎回作り直されるからです。

店の取り分

100 スクラップを賭けたときに、平均で減る量

  1. 基本戦略−0.8
  2. ルーレット (1・3・5)−4
  3. ディーラーと同じ引き方−5.9
  4. 12 以上で必ず止まる−6.0
  5. インシュランス−7.9
  6. ルーレット (20)−16

ブラックジャックの数字は、あとで説明する自作のプログラムでの概算です。ルーレットの数字は、コラム「ルーレットに必勝パターンはあるのか」のものです。

同じ台でも、打ち方で 7 倍以上の差が出ます。「なんとなく」で打つと、ルーレットより悪くなります。

インシュランスは取らない

見せ札が A のとき、伏せ札が 10 か絵札である確率は 159/518 = 30.7% です (伏せ札の位置には、切る前にそこにあった絵札 1 枚が来ないので、均等な切り方の 160/519 より少し下がります)。当たれば 3 倍が戻るので、平均は 3 × 0.307 − 1 = −7.9%。本体の賭けの 10 倍ほど割が悪い賭けです。自分の手が良くても悪くても、取らないほうが得です。

同じ動きをするプログラム

読んで分かった決まりを、自分で一から書いたプログラムです。ゲームのコードは写していません。山札、ディーラーの引き方、配当の部分はこれだけです。

DECKS = 10
VALUES = [2, 3, 4, 5, 6, 7, 8, 9, 10, 10, 10, 10, 11]  # 1 つのマーク。2〜K、最後が A (11)
SHOE = VALUES * 4 * DECKS                                # 順に並べた 520 枚。末尾が山のいちばん上

class Shoe:
    def __init__(self, rng, fair=False, cards=SHOE):
        self.cards, self.n, self.rng, self.fair = cards[:], len(cards), rng, fair

    def take(self):
        """上から 1 枚。位置 n を、n より下のどこかと入れ替えてから取る (n 自身は選ばない)"""
        self.n -= 1
        n = self.n
        if n:
            k = self.rng.randrange(n + 1 if self.fair else n)
            self.cards[k], self.cards[n] = self.cards[n], self.cards[k]
        return self.cards[n]

def dealer_draws(hard, ace):
    """hard は A を 1 と数えた合計。17 以上と、ソフト 18〜21 で止まる。ソフト 17 は引く"""
    return not (hard >= 17 or (ace and 18 <= hard + 10 <= 21))

def settle(cards, bet, dealer):
    """1 つの手の戻り。2 枚の 21 は 2.5 倍 (切り捨て)、勝ちは 2 倍、引き分けは等倍"""
    mine, natural = best(*state(cards)), len(cards) == 2 and best(*state(cards)) == 21
    if mine > 21:
        return 0
    house = best(*state(dealer))
    if len(dealer) == 2 and house == 21:
        return bet if natural else 0
    if house > 21:
        house = 0
    if mine > house or (mine == house and natural):
        return bet * 5 // 2 if natural else bet * 2
    return bet if mine == house else 0

state は手を「A を 1 と数えた合計」と「A があるか」に直し、best は A の 1 枚を 11 と数えられるときに数えた合計を返します (全体はファイルにあります)。

札を切るのは、位置ごとの入れ替えを「その札を取るとき」に行う形にしています。位置 n は自分の番の入れ替えのあと二度と動かないので、先に全部切ってから取るのと結果は同じです。乱数の方式は Python のものなので、出る札の並びはゲームと同じにはなりませんが、切り方と決まりは同じです。

take にも settle にも、前の回の結果・時刻・賭けた人を受け取る場所がありません。入ってくるのは乱数のもとと、その回の札だけです。

基本戦略は、同じプログラムの中で計算しています。山札を「どの数字も常に 13 分の 1 で出る」とみなして、手ごとにスタンド・ヒット・ダブル・スプリットの平均を比べ、いちばん良いものを選びます。上の表はその出力です。

配当の処理は、ポットを賭け金の少ない層から順に勝者へ渡していき、最後に「ポットが空になっているはず」と確かめる形です。台が何かを引く処理はありません。賭けられたスクラップは、全額がプレイヤーのだれかに戻ります。

だから、ポーカーには「店に対する平均の戻り」がありません。卓の全員の損得を足すと、いつも 0 です。勝てるかどうかは、相手より上手いかどうかだけで決まります。

よく聞く話を確かめる

「出た札を数えておけば、有利なときに大きく賭けられる」

成り立たないカードカウンティングは、使った札が山に戻らないまま次の回に進む場合にだけ効きます。この台は回ごとに 520 枚を作り直すので、数えた情報は次の回に持ち越せません。山札が作られるのは賭けの前なので、その回の札を見てから賭けることもできません。

「負けが続いた。台が貯め込んでいるから、そろそろ勝てる」

成り立たない台は、払った額も受け取った額も覚えていません。賭けたスクラップは回の終わりに消え、戻りは新しく作られます。回と回の間に持ち越されるのは、席と手持ちのスクラップだけです。

「大きく賭けると、悪い札が来る」

関係ない山札は賭けを受け付ける前に切り終わっています。札を切る処理にも、配る処理にも、賭けた額や人を見る場所がありません。

「ディーラーは、こちらの手を見て引き方を変える」

変えないディーラーが引くかどうかは、自分の札の合計だけで決まります。17 以上で止まり、ソフト 17 は引く。プレイヤーの手も賭け金も使われません。

「時間帯や、サーバーの人数で勝ちやすさが変わる」

変わらない乱数が使われるのは札を切る 1 か所だけで、OS の暗号用の乱数です。時刻も人数も入っていません。

「ディーラーの伏せ札は、ツールで覗ける」

送られていない回の途中、サーバーは伏せ札の中身をクライアントに送りません。ポーカーの他人の手札も同じです。手元の側をどう調べても、無いものは見えません。

「インシュランスは保険だから、良い手のときは取るべき」

取ると損インシュランスは本体とは別の賭けで、平均は −7.9% です。自分の手の良し悪しでは変わりません。

「負けたら倍にして賭け直せば、最後は勝てる」

平均は変わらない毎回の結果は前の回と関係しないので、賭ける額の順序で平均は動きません。上限が 500 なので、5 から始めても 7 回続けて負けると、次の倍 (640) はもう賭けられません。

「座る席で、来る札が変わる」

1 枚ぶんだけ変わる札は席の番号の順に配られ、切り方には上で書いた 1 枚ぶんのずれがあります。次の節で確かめます。勝ち負けを左右するほどの差ではありません。

「ポーカーは、台が強い手どうしをぶつけて盛り上げている」

していない52 枚を切って上から配るだけです。だれに何を配るかを選ぶ処理はありません。台には取り分が無いので、盛り上げる理由もありません。

席と、切り方のずれ

札は、ボタンの位置に関係なく、いつも番号のいちばん若い席から配られます。切り方のずれ (最初の 1 枚はクラブの A にならない) は、その席にそのまま出ます。

ポーカーを 2 人で遊ぶ場合に、それぞれの席がクラブの A を持つ割合を 100 万回数えました。

  1. 先に配られる席 (この台の切り方)1.97%
  2. あとに配られる席 (この台の切り方)3.91%
  3. どちらの席も (均等に切った場合)3.85%

先に配られる席は、クラブの A を持つことが半分しかありません。1 枚めには絶対に来ず、2 枚めでしか持てないからです。同じように、あとに配られる席はクラブの K が、場の札はクラブの 10・9・8 が、それぞれ 1 か所ずつ来ない位置を持っています。

では勝ち負けに効くかというと、ほとんど効きません。

  • ポーカー: 全員が最後まで降りないと仮定して 100 万回試すと、2 人ではポットの取り分に差は見えませんでした (49.97% と 50.03%、誤差 ±0.05)。6 人では、先頭の席が 16.57% で、等分の 16.67% より 0.1 ポイント低い程度でした (誤差 ±0.04)。
  • ブラックジャック: 520 枚のうちの 1 枚なので、さらに小さくなります。1 人で座ったとき、店の取り分が 0.09 ポイント増えると計算しました。3 人で座ると、番号のいちばん若い席が 0.15 ポイント、ほかの席が 0.03〜0.04 ポイントです。どれも計算だけの数字で、3 人で座る試行はしていません。3 人の数字は、記事のプログラムとは別の使い捨てのプログラムで出しました。

「この席は勝てない」と言えるほどの差ではありません。処理を読むと 1 枚ぶんのずれがある、という事実として書いておきます。

分からないこと

  • 番号のいちばん若い席が、どの位置か。 台のどの席が 0 番かは、確かめていません。
  • 役の判定の中身。 役を比べる部分は、よく知られた公開の評価器と同じ形の部品に任されています。その中身までは読んでいません。
  • 3 人以上のオールイン。 持ち金の少ない人がオールインして勝ったとき、サイドポットがふつうの決まりどおりに分かれるかどうか。処理を読むと、ふつうと違う配り方になりそうな箇所があります。実際に遊んで確かめてはいません。
  • 店の取り分の細かい桁。 約 0.8% は、自作のプログラムでの概算です。計算は山札を無限とみなした近似で、試行には ±0.05〜0.1 ポイントの誤差があります。
  • この記事の対象。 2026-11-07 の版の PC 版のサーバーで、賭け金の上限が既定の 500 の場合です。上限はサーバーごとに変えられ、決まりは今後のアップデートで変わることがあります。

調べ方

サーバー本体の処理 (ブラックジャックとポーカーのクラスの中間コード) を読み、台とテーブルの設定の値をデータのファイルから読みました。サーバーは起動していません。山札の枚数、ディーラーの引き方、配当の倍率、賭け金の範囲、ブラインド、時間は、どれも読んだ値です。

店の取り分、基本戦略の表、席ごとの割合は、読んだ決まりを自分で書き直したプログラムで計算・試行したものです。クラブの A を持つ割合までは card-games.py が出します。ポーカーのポットの取り分と、ブラックジャックの 3 人の席ごとの差は、別の使い捨てのプログラムで出しました。

ゲームの中で実際に遊んで数えた結果ではありません。処理がそう書かれている、という確認です。
