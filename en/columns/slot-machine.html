The slot machine loses more the more you spin. Average return is 91.8%

How the slot machine picks symbols and pays out, read from the server code and data. A 2 Scrap bet returns 1.84 on average. No machine or time pays better.

Answer

Bet 2 Scrap, get 1.84 back on average

On average, the return is 91.8% of the bet. All 3 symbols are decided the moment you pull the lever. Previous results, the time, the machine and the bet multiplier are not used. The more you spin, the more you lose on average.

  • −8.2%Average gain or loss (relative to the bet)
  • 12.4%Spins that return something (1 in 8)
  • 1/4,406Chance of three 7s

There is no lucky machine, no lucky time and no lucky way to spin. The only things that make a difference are "how many times you spin" and "how much you bet", and increasing either one increases the average loss.

How the slot machine works

One spin, step by step

  1. Insert ScrapAny amountOnly the seated player can insert. Choose a multiplier from 1 to 5
  2. Pull the leverInstantThe bet is taken, and the 3 symbols are decided at the same time
  3. Reels spin2.5 secOnly shows the symbols already decided
  4. PayoutInstantOn a win, Scrap goes into the payout slot

One bet is 2 Scrap. Raising the multiplier to 2–5 makes the bet 4, 6, 8 or 10, and the payout is multiplied by the same amount.

The symbols are decided before the reels start spinning. While they spin, the result can no longer change. There is no way to stop the reels. The slot machine has only 3 actions of its own: "spin", "put in or take out Scrap" and "change the multiplier" (the others are shared actions such as sitting down and standing up).

What is used to decide the symbols, and what is not

Used

  • The weight of each symbol (one setting shared by all machines)
  • A random number generator created fresh on the spot

Not used

  • The previous spin's symbols
  • Number of spins, number of losses
  • Time of day, player count on the server
  • Who is seated
  • Which machine
  • The bet multiplier

In plain words, the process that decides the symbols is as follows. It runs once for each of the 3 reels.

For one reel:
  Take one number from 0 to 999 as a seed
  Create a new random number generator from that seed, and use only its first number to pick a position from 0 to 329
  Look the position up in a table divided by each symbol's weight, and return one symbol

The random functions actually called

For each reel, these are called in this order. All of them are built-in methods of Unity and .NET, not a random number generator made by Rust itself.

OrderMethod calledWhat it decides
1UnityEngine.Random.Range(0, 1000)The seed. One integer from 0 to 999
2new System.Random(seed)Creates a new .NET random generator from that seed
3Next(0, 330)Where the reel stops. An integer from 0 to 329
  • The integer version of UnityEngine.Random.Range(min, max) includes min and excludes max. It returns 0 to 999.
  • System.Random(seed) always produces the same sequence of numbers from the same seed. The slot machine uses only the first number of the generator it creates, and creates a new one for the next reel. It never continues the sequence from the previous spin.
  • Next(0, 330) returns 0 to 329. 330 is the total of the symbol weights.

Each reel has only 1,000 outcomes

There are 1,000 seeds, 0 to 999, and the same seed always gives the same symbol. So one reel is the same as "a lottery of 1,000 tickets", with a fixed number of tickets for each symbol. We rewrote the System.Random algorithm that Microsoft publishes, computed each of the 1,000 seeds one by one, and counted.

The configured weights and the actual odds differ slightly

The settings give each symbol a weight of "so many out of 330". But there are only 1,000 seeds, and 1,000 is not divisible by 330, so the actual odds drift slightly from the weights.

A program that behaves the same way

This is a program written from scratch based on the behavior read from the code. No game code was copied. The spinning part and the payout part are all there is.

# REEL is the table of symbols that each of the 1,000 seeds gives (everything on one reel)
def spin(source):
    """One spin. Take one seed per reel and return that seed's symbol"""
    return tuple(REEL[source.randrange(1000)] for _ in range(3))

TRIPLES = {"charcoal": 15, "wood": 25, "rope": 40, "bandage": 45,
           "lowgrade": 80, "sulfur": 100, "scrap": 400, "seven": 1000}

def payout(faces, multiplier=1):
    """Scrap returned. 5 per Low Grade Fuel, plus the triple's payout if all three match, times the multiplier"""
    total = 5 * faces.count("lowgrade")
    if faces[0] == faces[1] == faces[2]:
        total += TRIPLES.get(faces[0], 0)
    return total * multiplier

The REEL table is built from each seed 0 to 999 by rewriting the System.Random algorithm that Microsoft publishes (the calculation that makes the first number from a seed). The part that takes the seed (source.randrange) uses Python's random numbers, so the order of results is not the same as in the game, but the mapping from seed to symbol is the same.

spin has no place to receive the previous result, the time, the machine or the multiplier. The only input is the source of randomness.

Calculation and simulated spins

The average return was obtained in 2 ways. One is a calculation that adds up every combination of symbols on the 3 reels (exact, using fractions). The other is the result of actually running this program.

Even with 1 million spins, the result was 0.35 points off the calculation. This is because the average moves when three 7s, worth 1,000, come up a few times more or less. As a rough guide to the spread (standard error), it is ±0.8 points at 1 million spins and still ±0.25 points at 10 million. That the 10 million spins with seed 7 nearly match the calculation is luck (10 million spins with seed 1 give 91.61%). When a few hundred or a few thousand spins make you feel "this machine pays" or "it's not paying today", this spread is what you are feeling.

In the 1 million spins, the longest streak of spins returning nothing was 115.

The full program is in slot-machine.py. python3 slot-machine.py gives the numbers for 1 million spins, and python3 slot-machine.py 10000000 7 for 10 million.

Checking common claims

"Some machines pay and some don't"

NoThere are 32 slot machines in the data, and all of them use the same single payout setting. Values such as the spin time are also the same. The process that decides the symbols does not look at which machine it is.

"If you keep spinning, a win is due soon"

Doesn't holdNothing anywhere counts the number of spins or losses. The random generator made from the seed is also created fresh for each reel and each spin. The Unity random generator that gives the seed is one generator shared across the whole server, and it advances regardless of how many times a slot machine has lost. Even after 50 losses, the chance that the next spin returns something stays at 12.4%.

"A higher multiplier wins more often (or less often)"

No effectThe multiplier is only applied equally to the bet and the payout. It is not part of the process that decides the symbols. Multiplier 5 is, on average, the same as betting 5 spins at multiplier 1 at once. Only the spread gets bigger.

"The timing of the lever pull changes the result"

Can't aimThe seed is taken from a random generator inside the server. We believe its state is not sent to players (estimated). All 3 symbols are decided the moment you pull, and there is no way to stop the reels. You cannot time the stops.

"Two 7s stopped. So close, the next one will hit"

UnrelatedThe 3 reels are decided separately, and two of a kind pays nothing. The previous spin's symbols are kept only for display and are not passed to the process that decides the next symbols. The chance of three 7s on the next spin is always 1 in 4,406.

"The odds change with the time of day or the server's player count"

No effectThe process that decides the symbols uses only the symbol weights and random numbers. Neither the time nor the number of players is part of it.

"Server admins can rig the results"

By default, only forcing a winThere is a server admin setting, slotmachine.forcepayoutindex. Its default is −1 (off). Set to 0–7, every machine on that server pays the win with that number in the payout table on every spin. It can only choose among the wins. It is not a setting that makes losing more likely. Servers that rewrite the process with plugins are outside the scope of this article. How each server sets this value cannot be checked from outside.

What we don't know

  • What is inside Unity's random generator. UnityEngine.Random.Range, which gives the seed, is inside the Unity engine itself and was not read this time. That 0 to 999 come up almost equally often relies on the Unity docs. That 3 seeds taken in a row are unrelated to each other is not stated in the docs. It is an assumption based on the nature of pseudo-random generators. The probabilities and average return in this article are calculated on that assumption.
  • What the screen shows. We have not looked at the symbol images or the payout table shown on the game screen. The symbol names come from the names in the data.
  • Scrap left in the bet slot. Payouts move to your inventory when you stand up. What happens to Scrap left in the bet slot when you stand up has not been checked.
  • Since when these payouts apply. The history of changes since the slot machine was added has not been researched.
  • Scope of this article. The PC server, version 2026-11-07. Future updates may change this.

How this was researched

We read the server's code (the intermediate code of the slot machine class), and read the payout settings and slot machine values from the data files. The server was not started. The bet of 2, the multipliers 1–5, the 2.5-second spin time, the symbol weights and the payout table are all values read from the files.

The tickets per symbol (out of 1,000) were computed seed by seed using a rewrite of the published .NET random algorithm. The rewrite was checked against well-known values (the first number for seed 0 is 1559595546, for seed 42 it is 1434747710). The probabilities and average return were calculated from those counts.

These are not results counted by actually spinning in the game. They confirm what the code says. The 1 million and 10 million spin results in the article come from running a self-written program that behaves the same way.
