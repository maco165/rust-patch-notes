블랙잭과 포커, 카드를 세면 이길 수 있을까?

블랙잭 머신과 Card Table을 서버 코드를 읽은 결과로 확인합니다. 덱은 매번 새로 만들어지므로 카드를 세어도 유리해지지 않습니다. 하우스 엣지는 약 0.8%입니다.

결론

카드를 세어도 유리해지지 않습니다

덱은 라운드가 시작될 때마다 새로 만들어 다시 섞습니다. 블랙잭은 10덱 520장, 포커는 1덱 52장입니다. 이전 라운드에 나온 카드는 다음 라운드에 아무것도 남기지 않습니다.

  • 520장블랙잭의 덱. 매번 새로 만든다
  • 약 −0.8%블랙잭을 기본 전략으로 쳤을 때의 평균 (추정)
  • 0포커에서 하우스가 가져가는 몫. 전액이 플레이어에게 돌아간다

블랙잭은 정석대로 치면 Big Wheel (가장 좋은 베팅으로 −4%)보다 훨씬 덜 잃는 게임입니다. 그래도 평균적으로는 줄어듭니다. 포커는 하우스의 몫이 없고, 손익은 상대와의 승패만으로 정해집니다.

이 글에서는 Bandit Camp 등에 있는 블랙잭 머신 (클래스 이름은 BlackjackMachine)과 Card Table (CardTable. 즐길 수 있는 게임은 텍사스 홀덤)을 다룹니다.

블랙잭은 이렇게 움직입니다

한 라운드의 흐름

  1. 덱을 만든다순식간10덱 520장을 새로 늘어놓고 섞는다. 베팅보다 먼저
  2. 베팅 접수최대 30초5~500 Scrap
  3. 카드 배분1초좌석 번호 순으로 2장씩. 딜러는 1장을 엎어 둔다
  4. 내 차례조작마다 30초모두가 동시에 진행한다
  5. 딜러 차례1초에 1장합계만 보고 기계적으로 뽑는다
  6. 배당1초 후4초 후에 다음 라운드

덱이 만들어지는 것은 베팅을 받기 전입니다. 베팅한 금액을 보고 나서 카드를 배열하는 코드는 없습니다.

카드를 정할 때 쓰는 것, 쓰지 않는 것

쓰는 것

  • 그 라운드를 위해 새로 늘어놓은 덱
  • 암호용 난수 (카드를 섞을 때만)
  • 카드 합계 (딜러가 뽑을지 말지)

쓰지 않는 것

  • 이전 라운드의 카드와 결과
  • 시각, 라운드 수
  • 서버 인원
  • 베팅한 금액
  • 베팅한 사람, 승패 기록
  • 머신이 지금까지 지급한 금액

베팅한 Scrap은 라운드가 끝날 때 사라지고, 환수분은 새로 만들어집니다. 머신은 "쌓인 몫"을 가지고 있지 않으므로, "슬슬 토해 낼" 상태라는 것이 애초에 없습니다.

덱을 섞는 방법

카드를 섞는 코드가 부르는 난수는 .NET에 기본으로 있는 System.Security.Cryptography.RandomNumberGenerator.GetInt32뿐입니다. OS의 암호용 난수로, 시드도 게임 안의 상태도 갖지 않습니다. Big Wheel이 쓰는 Unity의 난수와는 다른 것입니다.

섞는 방법을 말로 쓰면 이렇습니다.

새 덱을 만들 때:
  스페이드 2부터 클럽 A까지, 덱 수만큼 순서대로 늘어놓는다
  덱의 맨 위 위치부터 차례로 아래쪽으로:
    그 위치보다 "아래"의 어딘가 한 곳을 같은 확률로 골라 카드를 맞바꾼다
카드를 나눠 줄 때:
  맨 위에서 1장씩 가져간다

딱 1장만큼 균등에서 벗어나 있다

교과서적인 섞기 (Fisher–Yates)는 맞바꿀 상대에 "그 위치 자신"도 포함합니다. 카드가 우연히 움직이지 않는 일도 일어나도 되기 때문입니다. 이 머신의 섞기는 상대를 "그 위치보다 아래"에서만 고릅니다. Sattolo 방식이라고 불리는 형태로, 어떤 카드도 섞기 전에 있던 자리에는 절대로 남지 않습니다.

새 덱의 위에서 13장은 섞기 전에 이 순서입니다 (모두 클럽).

AKQJ1098765432

섞은 뒤 맨 위에 오는 카드는 "원래 맨 위에 있던 클럽 A"를 뺀 나머지 전부에서 같은 확률로 골라집니다. 2번째는 "원래 2번째에 있던 클럽 K"를 뺀 나머지에서 고르는 식으로 이어집니다. 즉, 처음 나눠 주는 1장은 그 클럽 A만은 절대 되지 않습니다.

덱첫 1장이 A일 확률균등하게 섞은 경우
블랙잭 (520장)39/519 = 7.51%40/520 = 7.69%
포커 (52장)3/51 = 5.88%4/52 = 7.69%

차이는 1장 분량입니다. 블랙잭의 하우스 엣지를 0.1포인트 정도 늘린다고 계산했습니다 (뒤의 절). 라운드를 넘어 치우침이 쌓이는 일은 없습니다. 덱은 매번 새로 만들어지기 때문입니다.

블랙잭의 숫자는 뒤에서 설명하는 직접 만든 프로그램으로 낸 추정치입니다. Big Wheel의 숫자는 칼럼 "Big Wheel에 필승 패턴이 있을까?"에서 가져왔습니다.

같은 머신이라도 치는 방법에 따라 7배 이상 차이가 납니다. "감으로" 치면 Big Wheel보다 나빠집니다.

인슈어런스는 하지 않는다

업카드가 A일 때 홀 카드가 10이나 그림 카드일 확률은 159/518 = 30.7%입니다 (홀 카드 자리에는 섞기 전에 그 자리에 있던 그림 카드 1장이 오지 않으므로, 균등하게 섞었을 때의 160/519보다 조금 낮아집니다). 맞으면 3배가 돌아오므로 평균은 3 × 0.307 − 1 = −7.9%. 본 베팅보다 10배 정도 효율이 나쁜 베팅입니다. 내 패가 좋든 나쁘든 하지 않는 편이 이득입니다.

똑같이 움직이는 프로그램

읽어서 알아낸 규칙을 직접 처음부터 쓴 프로그램입니다. 게임 코드는 베끼지 않았습니다. 덱, 딜러가 뽑는 방식, 배당 부분은 이것뿐입니다.

DECKS = 10
VALUES = [2, 3, 4, 5, 6, 7, 8, 9, 10, 10, 10, 10, 11]  # 한 무늬. 2~K, 마지막이 A (11)
SHOE = VALUES * 4 * DECKS                                # 순서대로 늘어놓은 520장. 끝이 덱의 맨 위

class Shoe:
    def __init__(self, rng, fair=False, cards=SHOE):
        self.cards, self.n, self.rng, self.fair = cards[:], len(cards), rng, fair

    def take(self):
        """위에서 1장. 위치 n을 n보다 아래의 어딘가와 맞바꾼 뒤 가져간다 (n 자신은 고르지 않는다)"""
        self.n -= 1
        n = self.n
        if n:
            k = self.rng.randrange(n + 1 if self.fair else n)
            self.cards[k], self.cards[n] = self.cards[n], self.cards[k]
        return self.cards[n]

def dealer_draws(hard, ace):
    """hard는 A를 1로 센 합계. 17 이상과 소프트 18~21에서 멈춘다. 소프트 17은 뽑는다"""
    return not (hard >= 17 or (ace and 18 <= hard + 10 <= 21))

def settle(cards, bet, dealer):
    """패 하나의 환수. 2장 21은 2.5배 (버림), 승리는 2배, 무승부는 1배"""
    mine, natural = best(*state(cards)), len(cards) == 2 and best(*state(cards)) == 21
    if mine > 21:
        return 0
    house = best(*state(dealer))
    if len(dealer) == 2 and house == 21:
        return bet if natural else 0
    if house > 21:
        house = 0
    if mine > house or (mine == house and natural):
        return bet * 5 // 2 if natural else bet * 2
    return bet if mine == house else 0

state는 패를 "A를 1로 센 합계"와 "A가 있는지"로 바꾸고, best는 A 1장을 11로 셀 수 있을 때 그렇게 센 합계를 돌려줍니다 (전체는 파일에 있습니다).

섞기는 위치마다의 맞바꾸기를 "그 카드를 가져갈 때" 하는 형태로 했습니다. 위치 n은 자기 차례의 맞바꾸기 뒤로는 다시 움직이지 않으므로, 먼저 전부 섞은 뒤 가져가는 것과 결과가 같습니다. 난수 방식은 Python의 것이므로 나오는 카드 순서는 게임과 같지 않지만, 섞는 방법과 규칙은 같습니다.

take에도 settle에도 이전 라운드의 결과, 시각, 베팅한 사람을 받는 자리가 없습니다. 들어오는 것은 난수의 원천과 그 라운드의 카드뿐입니다.

기본 전략은 같은 프로그램 안에서 계산합니다. 덱을 "어떤 숫자든 항상 13분의 1로 나온다"고 보고, 패마다 스탠드, 히트, 더블, 스플릿의 평균을 비교해 가장 좋은 것을 고릅니다. 위의 표가 그 출력입니다.

배당 코드는 팟을 베팅액이 적은 층부터 차례로 승자에게 건네고, 마지막에 "팟이 비어 있어야 한다"고 확인하는 형태입니다. 테이블이 무언가를 떼어 가는 코드는 없습니다. 걸린 Scrap은 전액이 플레이어 중 누군가에게 돌아갑니다.

그래서 포커에는 "하우스에 대한 평균 환수"가 없습니다. 테이블 전원의 손익을 더하면 항상 0입니다. 이길 수 있는지는 상대보다 잘하는지만으로 정해집니다.

자주 듣는 이야기를 확인한다

"나온 카드를 세어 두면 유리할 때 크게 걸 수 있다"

성립하지 않는다카드 카운팅은 쓴 카드가 덱에 돌아가지 않은 채 다음 라운드로 넘어갈 때만 통합니다. 이 머신은 라운드마다 520장을 새로 만들므로, 센 정보를 다음 라운드로 가져갈 수 없습니다. 덱은 베팅 전에 만들어지므로, 그 라운드의 카드를 보고 나서 거는 것도 불가능합니다.

"계속 졌다. 머신이 쌓아 두고 있으니 슬슬 이긴다"

성립하지 않는다머신은 지급한 금액도 받은 금액도 기억하지 않습니다. 베팅한 Scrap은 라운드가 끝날 때 사라지고, 환수분은 새로 만들어집니다. 라운드와 라운드 사이에 이어지는 것은 좌석과 가진 Scrap뿐입니다.

"크게 걸면 나쁜 카드가 온다"

관계없다덱은 베팅을 받기 전에 다 섞여 있습니다. 섞는 코드에도 나눠 주는 코드에도 베팅액이나 사람을 보는 자리가 없습니다.

"딜러는 내 패를 보고 뽑는 방식을 바꾼다"

바꾸지 않는다딜러가 뽑을지는 자기 카드의 합계만으로 정해집니다. 17 이상에서 멈추고, 소프트 17은 뽑습니다. 플레이어의 패도 베팅액도 쓰이지 않습니다.

"시간대나 서버 인원에 따라 이기기 쉬움이 달라진다"

달라지지 않는다난수가 쓰이는 곳은 카드를 섞는 한 곳뿐이고, OS의 암호용 난수입니다. 시각도 인원도 들어가지 않습니다.

"딜러의 홀 카드는 툴로 엿볼 수 있다"

전송되지 않는다라운드 도중에 서버는 홀 카드의 내용을 클라이언트에 보내지 않습니다. 포커에서 다른 사람의 핸드도 마찬가지입니다. 내 쪽을 아무리 조사해도 없는 것은 보이지 않습니다.

"인슈어런스는 보험이니까 좋은 패일 때는 해야 한다"

하면 손해인슈어런스는 본 베팅과 별개의 베팅이고, 평균은 −7.9%입니다. 내 패가 좋은지 나쁜지로는 달라지지 않습니다.

"지면 두 배로 다시 걸면 결국 이긴다"

평균은 달라지지 않는다매번의 결과는 이전 라운드와 관계가 없으므로, 거는 금액의 순서로 평균은 움직이지 않습니다. 상한이 500이므로 5에서 시작해도 7번 연속으로 지면 다음 두 배 (640)는 더 이상 걸 수 없습니다.

"앉는 자리에 따라 오는 카드가 달라진다"

1장 분량만 달라진다카드는 좌석 번호 순으로 나눠 주고, 섞기에는 위에서 쓴 1장 분량의 치우침이 있습니다. 다음 절에서 확인합니다. 승패를 좌우할 만한 차이는 아닙니다.

"포커는 테이블이 강한 패끼리 붙여서 분위기를 띄운다"

하지 않는다52장을 섞어서 위에서 나눠 줄 뿐입니다. 누구에게 무엇을 줄지 고르는 코드는 없습니다. 테이블은 몫을 가져가지 않으므로 분위기를 띄울 이유도 없습니다.

좌석과 섞기의 치우침

카드는 버튼의 위치와 관계없이 항상 번호가 가장 작은 좌석부터 나눠 줍니다. 섞기의 치우침 (첫 1장은 클럽 A가 되지 않는다)은 그 좌석에 그대로 나타납니다.

포커를 2명이 할 때, 각 좌석이 클럽 A를 가지는 비율을 100만 번 세었습니다.

  1. 먼저 받는 좌석 (이 머신의 섞기)1.97%
  2. 나중에 받는 좌석 (이 머신의 섞기)3.91%
  3. 어느 좌석이든 (균등하게 섞은 경우)3.85%

먼저 받는 좌석은 클럽 A를 가지는 일이 절반밖에 없습니다. 1번째 장으로는 절대 오지 않고, 2번째 장으로만 받을 수 있기 때문입니다. 마찬가지로 나중에 받는 좌석은 클럽 K가, 보드 카드는 클럽 10, 9, 8이 각각 한 곳씩 오지 않는 위치를 가지고 있습니다.

그렇다면 승패에 영향이 있느냐 하면, 거의 없습니다.

  • 포커: 모두가 끝까지 폴드하지 않는다고 가정하고 100만 번 시험하면, 2명일 때는 팟 몫에 차이가 보이지 않았습니다 (49.97%와 50.03%, 오차 ±0.05). 6명일 때는 맨 앞 좌석이 16.57%로, 균등한 16.67%보다 0.1포인트 낮은 정도였습니다 (오차 ±0.04).
  • 블랙잭: 520장 중 1장이므로 더 작아집니다. 혼자 앉았을 때 하우스 엣지가 0.09포인트 늘어난다고 계산했습니다. 3명이 앉으면 번호가 가장 작은 좌석이 0.15포인트, 다른 좌석이 0.03~0.04포인트입니다. 모두 계산만으로 낸 숫자이고, 3명이 앉는 시뮬레이션은 하지 않았습니다. 3명의 숫자는 이 글의 프로그램과는 다른 일회용 프로그램으로 냈습니다.

"이 자리는 이길 수 없다"고 말할 만한 차이는 아닙니다. 코드를 읽으면 1장 분량의 치우침이 있다는 사실로 적어 둡니다.

알 수 없는 것

  • 번호가 가장 작은 좌석이 어느 위치인지. 테이블의 어느 좌석이 0번인지는 확인하지 않았습니다.
  • 족보 판정의 내부. 족보를 비교하는 부분은 잘 알려진 공개 평가기와 같은 형태의 부품에 맡겨져 있습니다. 그 내부까지는 읽지 않았습니다.
  • 3명 이상의 올인. 가진 돈이 적은 사람이 올인해서 이겼을 때, 사이드 팟이 일반 규칙대로 나뉘는지. 코드를 읽으면 일반과 다른 방식으로 나눌 것 같은 부분이 있습니다. 실제로 플레이해서 확인하지는 않았습니다.
  • 하우스 엣지의 세세한 자릿수. 약 0.8%는 직접 만든 프로그램으로 낸 추정치입니다. 계산은 덱을 무한으로 간주한 근사이고, 시뮬레이션에는 ±0.05~0.1포인트의 오차가 있습니다.
  • 이 글의 대상. 2026-11-07 버전의 PC판 서버에서, 베팅 상한이 기본값 500인 경우입니다. 상한은 서버마다 바꿀 수 있고, 규칙은 앞으로의 업데이트에서 바뀔 수 있습니다.

조사 방법

서버 본체의 코드 (블랙잭과 포커 클래스의 중간 코드)를 읽고, 머신과 테이블의 설정값을 데이터 파일에서 읽었습니다. 서버는 실행하지 않았습니다. 덱의 장수, 딜러가 뽑는 방식, 배당 배율, 베팅액 범위, 블라인드, 시간은 모두 읽은 값입니다.

하우스 엣지, 기본 전략 표, 좌석별 비율은 읽은 규칙을 직접 다시 쓴 프로그램으로 계산하고 시뮬레이션한 것입니다. 클럽 A를 가지는 비율까지는 card-games.py가 냅니다. 포커의 팟 몫과 블랙잭 3명의 좌석별 차이는 별도의 일회용 프로그램으로 냈습니다.

게임 안에서 실제로 플레이해서 센 결과가 아닙니다. 코드가 그렇게 쓰여 있다는 확인입니다.
