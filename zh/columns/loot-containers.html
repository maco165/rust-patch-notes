箱子里的物品是什么时候决定的？

Barrel、Military Crate 和 Locked Crate 里的物品是何时、如何决定的？我们从服务器代码中确认：物品在箱子刷出时就已决定，不会因开箱的人或时间而改变。

结论

箱内物品在箱子刷出时就已决定

而不是在打开时决定。箱子出现在服务器上的那一刻，抽取就已完成，实际的物品被放进箱子里。开箱的人、时间、地点和附近的玩家都不参与抽取。

  • 0 次打开箱子时进行的抽取
  • 60～120 分钟遗迹中 Barrel、Crate、Military Crate 的物品重置间隔
  • 52%Elite Crate 里至少出 1 把枪的概率

以下是阅读 2026-11-07 版本的服务器代码和数据得出的结果。

箱子的一生

  1. 刷出一瞬间抽取在此完成，物品放入箱中
  2. 放置中60～120 分钟箱内物品不变
  3. 重置一瞬间清空全部物品，重新抽取
  4. 被搜空—箱子消失，之后会刷出新的箱子
  • 打开这一步只记录第一个打开的人，不进行抽取。
  • 重启后从存档恢复的箱子，不重新抽取，而是恢复原来的物品。

抽取用到的和用不到的

用到的

  • 每种箱子的设置（槽位列表、Scrap 的数量）
  • 掉落表（权重和数量）
  • 随机数
  • 服务器的时代设定

用不到的

  • 开箱的人
  • 时间、清档后的天数
  • 箱子的位置
  • 附近的玩家、服务器人数
  • 之前出过的物品
  • 打开或破坏的方式

箱内物品的决定方式

抽取分为 2 级：每个箱子的“槽位”，以及槽位所抽取的“表”。

箱子刷出时：
  从上到下依次查看箱子的槽位
    每个槽位，重复固定次数：
      若 0 到 1（含两端）的随机数不大于该槽位的概率，就从该槽位的表中抽取 1 次
  按箱子固定的数量放入 Scrap

从表中抽取 1 次：
  若表中列的是下级表，按权重比例选 1 个，再从那个表中抽取（重复直到叶节点）
  若表中列的是物品（叶节点），把列出的物品全部放入

抽取使用的随机数只有 Unity 自带的 UnityEngine.Random.Range。

4 个意外发现

数量的“最大值”不会出现

数量是“在最小值到最大值之间取实数再向下取整”，所以最大值几乎不会出现。

MLRS Rocket（Elite Crate 的槽位）1～2必定 1

是否以蓝图形式出现，是按物品固定的。以蓝图形式出现的只有 12 种（Barbeque、Wheelbarrow Piano、Minicopter 等）。

抽到相同物品不会重抽

同一物品命中 2 次，就会照样放入 2 个。超出箱子格数的物品会消失（Bradley Crate 中为 6%）。

有抽取次数为 0 的槽位

Crate 的“炮塔零件 4%”槽位抽取次数为 0，永远不会命中。

行为相同的程序

这是我们从零编写、行为相同的程序（没有复制游戏代码）。示例只包含 Military Crate 的零件表和几个小槽位。

def roll_amount(amount, maximum, rng):
    """在最小值到最大值之间取实数，舍去小数。最大值本身不会出现"""
    if maximum > 0 and maximum > amount:
        return max(1, int(rng.uniform(amount, maximum)))
    return max(1, int(amount))

def spawn(table, rng, box):
    """从表中抽取 1 次。有下级表就按权重选 1 个，到达叶节点就全部放入"""
    subs = TABLES.get(table)
    if subs:
        left = sum(weight for weight, _ in subs)
        pick = rng.randrange(left)
        for weight, name in subs:
            left -= weight
            if pick >= left:
                spawn(name, rng, box)
                return
    for item, amount, maximum in ITEMS.get(table, []):
        box[item] += roll_amount(amount, maximum, rng)

def fill(rng):
    """1 个箱子。开箱的人、时间、地点都不参与。只有表和随机数"""
    box = collections.Counter()
    for table, tries, chance in SLOTS:
        for _ in range(tries):
            if rng.random() <= chance:
                spawn(table, rng, box)
    box["scrap"] += SCRAP
    return box

验证常见说法

“开箱的人不同，物品也不同”

不会变箱子刷出时物品就已经在里面了，打开这一步不进行抽取。不管谁打开，同一个箱子出的都是同样的东西。

“人少的时段容易出好东西”

不会变抽取既不使用时间，也不使用服务器人数。人数只影响被搜空的箱子重新刷出的速度。

“Locked Crate 的物品在破解完成时才决定”

放置时就已决定Locked Crate 也是在出现时就完成抽取。那 15 分钟只是能够打开之前的等待时间。

“Barrel 掉落的东西取决于破坏方式”

不会变Barrel 的物品同样在刷出时就已决定，破坏后会原样掉出里面的东西。只有增加 Scrap 的效果所带来的额外部分，是在破坏时才加上的。

“只留下一点东西，那个箱子就会一直保持原样”

时间到了就会重置遗迹中的箱子即使留下东西也不会消失，但到了 60～120 分钟的重置时，剩下的东西会被清除，换成新的物品。路边垃圾堆的箱子，只要拿走 1 件，玩家离开 90 秒后整个垃圾堆就会消失。搜空的箱子要几分钟才会重新刷出，我们还没有调查。

“出过好东西的箱子位置，下次也会出好东西”

没有关系抽取既不使用箱子的位置，也不使用之前出过的物品。每次只是从同样的表重新抽取。

“一直刷 Military Crate，总有一天会出 Timed Explosive Charge（C4）”

不会出Military Crate 的表里没有 Timed Explosive Charge（C4）。想从箱子里拿，就去找 Bradley Crate（36%）、Supply Drop（27%）、Heli Crate（26%）、Locked Crate（9.6%）或 Elite Crate（1.9%）。

尚不清楚的事

  • 重置时间为无穷大的箱子。 Elite Crate 和 Locked Crate 的重置时间被设为无穷大。计时器的设计是“到了预定时间才执行”，所以设为无穷大可以理解为永远不执行。不过，Unity 的随机数在收到无穷大时会返回什么，属于 Unity 引擎内部，我们没有确认。
  • 重新刷出的间隔和位置。 被搜空的箱子要几分钟才重新刷出、哪个位置刷出哪种箱子，因为没有读遗迹的数据，所以不清楚。
  • 游戏模式的加成。 抽取的权重有按游戏模式追加加成的机制。普通模式没有加成，本文的数字都是这种情况下的。服务器的时代设定按默认（无限制）处理。Hardcore、Primitive 等模式下数字会变。
  • 与箱子外观的对应。 预制体名与游戏中箱子的外观和名称的对应关系，是根据预制体名推测的。
  • 本文的对象。 本文针对 2026-11-07 版本。表的权重经常随更新而变化。
  • 2020 年 Supply Drop 的抽取次数。 “8 次”是现在 Supply Drop 箱子里残留的旧设置（maxDefinitionsToSpawn 8）。没有槽位的箱子按这个次数抽取表的代码至今仍在，但 2020 年的值是否为 8，我们没有确认。
  • 2020 年的代码。 旧版本的服务器无法获取，所以 2020-11 和 2021-08 只读了客户端的表，并假定是否以蓝图形式出现与现在一样由物品的标记（spawnAsBlueprint）决定来计算。与 2021-08 的差异中，也包含 Tech Tree Update 以外的更新带来的变化。
  • 2020 年以前。 年表中更早的条目只依据官方更新日志的文字。

调查方法

我们阅读了服务器代码、105 个箱子设置和 1,327 个掉落表（没有运行服务器）。概率由表计算得出，并确认与自编程序的 10 万个箱子在 0.5 个百分点以内吻合（“至少 1 把枪”和 Bradley 为试验值）。旧版本的表用 scripts/dump_loot_spawns.py 读取。这些不是在游戏中打开箱子计数得到的结果。
