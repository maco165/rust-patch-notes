老虎机越转越亏，平均返还率 91.8%

我们从服务器代码和数据中读出了老虎机图案的决定方式和赔付。下注 2 Scrap，平均只返还 1.84。既没有容易出奖的机器，也没有容易出奖的时间段。

结论

下注 2 Scrap，平均返还 1.84

平均返还是赌注的 91.8%。拉下拉杆的一瞬间，3 个图案就全部定好了，不会用到之前的结果、时间、机器，也不会用到下注倍率。转得越多，平均亏得越多。

  • −8.2%平均盈亏（相对于赌注）
  • 12.4%有任何返还的次数（8 次里 1 次）
  • 1/4,4063 个 7 连成一线的概率

没有容易出奖的机器，没有容易出奖的时间，也没有容易出奖的转法。会带来差别的只有“转多少次”和“下注多少”，两者越多，平均亏损就越大。

老虎机是这样运作的

一次的流程

  1. 投入 Scrap任意数量只有坐在座位上的人才能投入。可选择 1～5 倍的倍率
  2. 拉下拉杆一瞬间扣除赌注，同时决定 3 个图案
  3. 转轴转动2.5 秒只是把已经定好的图案展示出来
  4. 赔付一瞬间中奖时，Scrap 会放进领取栏

一次下注是 2 Scrap。把倍率提高到 2～5，赌注就变成 4、6、8、10，赔付也按同样的倍数增加。

图案是在转轴开始转动之前决定的。转动期间，结果已经不会再变。也没有让转轴停下的操作。老虎机特有的操作只有“转动”“投入或取出 Scrap”“更改倍率”这 3 种（其他是坐下、站起等通用操作）。

决定图案时用到的和用不到的

用到的

  • 每种图案的权重（所有机器共用的同一套设置）
  • 当场重新生成的随机数

用不到的

  • 上一次的图案
  • 转动次数、未中奖次数
  • 时间、服务器人数
  • 坐着的是谁
  • 是哪一台机器
  • 下注倍率

用文字描述决定图案的处理，就是下面这样。3 个转轴各执行一次同样的操作。

一个转轴:
  从 0 到 999 中取 1 个数作为种子
  用这个种子新建一个随机数生成器，只用它的第 1 个数决定 0 到 329 之间的位置
  把位置套进按各图案权重划分的表，返回 1 个图案

实际调用的随机数

每个转轴按下面的顺序调用。它们都是 Unity 和 .NET 自带的方法，并不是 Rust 自己做的随机数。

顺序调用的方法决定什么
1UnityEngine.Random.Range(0, 1000)种子。0～999 中的 1 个整数
2new System.Random(种子)用这个种子新建一个 .NET 随机数生成器
3Next(0, 330)停下的位置。0～329 的整数
  • UnityEngine.Random.Range(最小值, 最大值) 的整数版本包含最小值、不包含最大值。返回的是 0～999。
  • System.Random(种子) 用同一个种子总是生成同样的数列。老虎机只用新建的生成器的第 1 个数，下一个转轴又会重新生成。不会接着上一次的数列继续。
  • Next(0, 330) 返回 0～329。330 是图案权重的总和。

一个转轴只有 1,000 种结果

种子是 0～999 共 1,000 个，同一个种子一定出同一个图案。也就是说，一个转轴就等于“1,000 张的抽签”，每种图案的张数是固定的。我们自己重写了 Microsoft 公开的 System.Random 算法，把 1,000 个种子逐个算出并做了统计。

行为相同的程序

这是根据读出的行为，我们从零自己写的程序，没有照抄游戏代码。转动部分和赔付部分就只有这些。

# REEL 是 1,000 个种子各自对应的图案表（一个转轴的全部）
def spin(source):
    """一次。每个转轴取 1 个种子，给出该种子的图案"""
    return tuple(REEL[source.randrange(1000)] for _ in range(3))

TRIPLES = {"charcoal": 15, "wood": 25, "rope": 40, "bandage": 45,
           "lowgrade": 80, "sulfur": 100, "scrap": 400, "seven": 1000}

def payout(faces, multiplier=1):
    """返还的 Scrap。每个 Low Grade Fuel 计 5，3 个相同再加上对应赔付，最后乘以倍率"""
    total = 5 * faces.count("lowgrade")
    if faces[0] == faces[1] == faces[2]:
        total += TRIPLES.get(faces[0], 0)
    return total * multiplier

REEL 表是重写 Microsoft 公开的 System.Random 算法（由种子算出第 1 个数的计算），从种子 0～999 逐个生成的。取种子的部分（source.randrange）用的是 Python 的随机数，所以出现的顺序和游戏中不同，但从种子到图案的对应关系是一样的。

spin 里没有接收上一次结果、时间、机器或倍率的地方。传进来的只有随机数的来源。

计算与实际转动的结果

平均返还用 2 种方法求出。一种是把 3 个转轴所有图案组合全部加总的计算（用分数精确计算）。另一种是实际运行这个程序的结果。

方法平均返还（相对于赌注 2）比例有任何返还的次数3 个 7
计算（实际的 1,000 种）1.836891.84%12.43%每 4,406 次 1 次
计算（完全按设置权重时）1.858992.95%13.04%每 4,492 次 1 次
转 100 万次的结果（随机数种子为 1）1.843892.19%12.45%231 次
转 1,000 万次的结果（随机数种子为 7）1.836991.85%12.45%2,257 次

即使转了 100 万次，也和计算值相差 0.35 个百分点。这是因为 3 个 7 的 1,000 多出几次或少出几次，平均值就会变动。波动的大致范围（标准误差）在 100 万次时为 ±0.8 个百分点，到 1,000 万次也还有 ±0.25 个百分点。种子 7 的 1,000 万次几乎和计算值重合，纯属巧合（种子 1 转 1,000 万次是 91.61%）。几百次、几千次的体感中觉得“这台机器容易出”“今天不出”，感受到的正是这种波动。

在 100 万次中，连续没有任何返还的最长纪录是 115 次。

完整程序放在 slot-machine.py。python3 slot-machine.py 给出 100 万次的数字，python3 slot-machine.py 10000000 7 给出 1,000 万次的数字。

验证常见说法

“有容易出奖的机器，也有不出奖的机器”

没有数据中的老虎机共有 32 台，全部使用同一套赔付设置。转动时间等数值也相同。决定图案的处理不会看是哪一台机器。

“一直连续转，差不多该中了”

不成立任何地方都没有统计转动次数或未中奖次数。由种子生成的随机数，也是每个转轴、每次都重新生成。给出种子的 Unity 随机数在整个服务器共用一个，它的推进与老虎机未中奖的次数无关。即使连续 50 次没中，下一次有任何返还的概率仍然是 12.4%。

“提高倍率更容易中（或者更难中）”

没有变化倍率只是同样地乘在赌注和赔付上，不参与决定图案的处理。倍率 5 平均来说等于把 5 次倍率 1 合在一起下注，只是波动变大。

“拉杆的时机会改变结果”

无法瞄准种子取自服务器内部的随机数。我们认为它的状态不会发送给玩家（推测）。拉下的一瞬间 3 个图案就全部定好，也没有让转轴停下的操作，所以无法靠眼力看准时机停轴。

“停了 2 个 7，差一点，下次就会来”

没有关系3 个转轴是分别决定的，2 个相同没有赔付。上一次的图案只是为了显示而保存下来，不会传给决定下一次图案的处理。下一次 3 个 7 连成一线的概率永远是每 4,406 次 1 次。

“出奖情况会随时间段或服务器人数变化”

没有变化决定图案的处理只用图案权重和随机数，不包含时间，也不包含玩家人数。

“服务器管理员可以操控结果”

标准设置下只能固定中奖服务器有一个管理员用的设置 slotmachine.forcepayoutindex。默认值是 −1（无效），设为 0～7 时，该服务器所有机器每次都会给出赔付表中该编号的中奖。能选的只是中奖的种类，并不是让人更容易不中的设置。用插件改写了处理的服务器不在本文范围内。各服务器如何设置这个值，从外部无法确认。

与转盘相比

把同一版本转盘的平均返还并列比较（下注 100 Scrap 时平均亏损的数量）。

  1. 转盘的 1/3/5−4
  2. 老虎机−8.2
  3. 转盘的 10−12
  4. 转盘的 20−16

下注同样的金额，老虎机亏损的速度是转盘 1/3/5 的 2 倍。而且一次最短只要 2.5 秒，单位时间内下注的次数很容易变多。

尚不清楚的地方

  • Unity 随机数的内部。 取种子的 UnityEngine.Random.Range 位于 Unity 引擎内部，这次没有阅读。0～999 几乎等概率出现，依据的是 Unity 文档的说明。连续取出的 3 个种子彼此无关，文档中并没有写，这是基于伪随机数性质的前提。本文的概率和平均返还都是在这个前提下计算的。
  • 画面显示。 我们没有看过图案的图片和游戏画面上显示的赔付表。图案的名称是根据数据中的名字起的。
  • 留在下注栏里的 Scrap。 赔付会在离开座位时移到背包里。一直放在下注栏里的 Scrap 在离开座位时会怎样，还没有确认。
  • 这套赔付从何时开始。 老虎机加入以来的变更经过没有调查。
  • 本文的对象。 2026-11-07 版本的 PC 版服务器。今后的更新可能会带来变化。

调查方法

我们阅读了服务器本体的代码（老虎机类的中间代码），并从数据文件中读取了赔付设置和老虎机的数值。没有启动服务器。赌注 2、倍率 1～5、转动时间 2.5 秒、图案权重、赔付表，都是读出的数值。

每种图案的张数（1,000 张中）是重写公开的 .NET 随机数算法后，逐个种子计算得出的。重写的算法是否正确，通过与广为人知的数值一致来确认（种子 0 的第 1 个数是 1559595546，种子 42 是 1434747710）。概率和平均返还是由这些张数计算出来的。

这不是在游戏中实际转动统计得到的结果，而是确认代码就是这样写的。文中 100 万次、1,000 万次的结果，是运行我们自己写的、行为相同的程序得到的。
