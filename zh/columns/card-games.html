21 点和扑克，靠算牌能赢吗？

根据阅读服务器代码的结果，检验 21 点机台和牌桌。牌堆每局都会重新生成，算牌不会带来任何优势。庄家优势约为 0.8%。

结论

算牌不会让你占到任何优势

每局开始时，牌堆都会重新生成并洗牌。21 点用 10 副 520 张，扑克用 1 副 52 张。上一局发出的牌，不会给下一局留下任何影响。

  • 520 张21 点的牌堆。每局重新生成
  • 约 −0.8%21 点按基本策略玩时的平均结果（估算）
  • 0扑克中庄家抽取的部分。全部返还给玩家

21 点只要按规矩打，亏损速度比转盘（最好的下注方式是 −4%）慢得多。但平均来说仍然会亏。扑克没有庄家抽成，输赢只取决于你和其他玩家之间的胜负。

本文讨论的是 Bandit Camp 等地的 21 点机台（类名 BlackjackMachine）和牌桌（CardTable，可玩的是德州扑克）。

21 点是这样运作的

一局的流程

  1. 生成牌堆瞬间重新排好 10 副 520 张并洗牌。在下注之前
  2. 接受下注最长 30 秒5～500 Scrap
  3. 发牌1 秒按座位编号顺序每人 2 张。庄家有 1 张暗牌
  4. 玩家回合每次操作 30 秒所有人同时进行
  5. 庄家回合每秒 1 张只看点数合计，机械地要牌
  6. 赔付1 秒后4 秒后开始下一局

牌堆是在接受下注之前生成的。不存在看了下注金额再去排牌的代码。

决定发牌时用到的和用不到的

用到的

  • 为这一局重新排好的牌堆
  • 加密用的随机数（只在洗牌时）
  • 牌的点数合计（庄家是否要牌）

用不到的

  • 之前各局的牌和结果
  • 时间、局数
  • 服务器人数
  • 下注金额
  • 下注者、其输赢记录
  • 机台至今已赔出的金额

下注的 Scrap 在一局结束时消失，返还的部分是新生成的。机台并不持有“攒下来的钱”，所以根本不存在“差不多该吐钱了”这种状态。

牌堆的洗法

洗牌代码调用的随机数只有 .NET 自带的 System.Security.Cryptography.RandomNumberGenerator.GetInt32。这是操作系统的加密用随机数，没有种子，也不带任何游戏内的状态。它和转盘使用的 Unity 随机数是两回事。

用文字描述洗牌方式，就是下面这样。

生成新牌堆时：
  从黑桃 2 到梅花 A，按副数依次排好
  从牌堆最上方的位置开始，依次向下：
    在该位置“下方”的某处等概率选 1 个位置，交换两张牌
发牌时：
  从最上方每次取 1 张

只有 1 张牌的偏差

教科书上的洗法（Fisher–Yates）会把“该位置本身”也算进交换对象，因为牌碰巧不动也是允许的。这台机器只从“该位置下方”选交换对象。这种形式称为 Sattolo 算法，任何一张牌都绝不会留在洗牌前自己所在的位置。

新牌堆最上面的 13 张，洗牌前是这个顺序（全是梅花）。

AKQJ1098765432

洗牌后，最上面的牌从“原本在最上面的梅花 A”以外的所有牌中等概率选出。第 2 张从“原本在第 2 位的梅花 K”以外的牌中选出，依此类推。也就是说，发出的第 1 张牌唯独不会是那张梅花 A。

扑克（52 张）3/51 = 5.88%4/52 = 7.69%

偏差只有 1 张牌的份量。我们计算出它会让 21 点的庄家优势增加约 0.1 个百分点（见后文）。由于牌堆每局重新生成，偏差不会跨局累积。

庄家优势

每下注 100 Scrap 平均亏损的量

  1. 基本策略−0.8
  2. 转盘（1、3、5）−4
  3. 照庄家的方式要牌−5.9
  4. 12 点及以上必停−6.0
  5. 保险−7.9
  6. 转盘（20）−16

21 点的数字是用后文介绍的自制程序得出的估算。转盘的数字取自专栏《Big Wheel 转盘有必胜规律吗？》。

同一台机器，打法不同差距可达 7 倍以上。“凭感觉”打的话，结果比转盘还差。

不要买保险

庄家明牌是 A 时，暗牌是 10 或人头牌的概率是 159/518 = 30.7%（暗牌所在的位置不会出现洗牌前在那里的那 1 张人头牌，所以比均匀洗牌时的 160/519 略低）。命中返还 3 倍，平均为 3 × 0.307 − 1 = −7.9%。这比主注差了约 10 倍。无论自己的手牌好坏，不买更划算。

行为相同的程序

这是我们根据读懂的规则，自己从零写的程序。没有抄游戏代码。牌堆、庄家要牌方式和赔付的部分就是下面这些。

DECKS = 10
VALUES = [2, 3, 4, 5, 6, 7, 8, 9, 10, 10, 10, 10, 11]  # 一种花色。2～K，最后是 A（11）
SHOE = VALUES * 4 * DECKS                                # 按顺序排好的 520 张。末尾是牌堆最上方

class Shoe:
    def __init__(self, rng, fair=False, cards=SHOE):
        self.cards, self.n, self.rng, self.fair = cards[:], len(cards), rng, fair

    def take(self):
        """从上方取 1 张。先把位置 n 与 n 下方的某处交换，再取牌（不会选 n 本身）"""
        self.n -= 1
        n = self.n
        if n:
            k = self.rng.randrange(n + 1 if self.fair else n)
            self.cards[k], self.cards[n] = self.cards[n], self.cards[k]
        return self.cards[n]

def dealer_draws(hard, ace):
    """hard 是把 A 算作 1 的合计。17 及以上和软 18～21 停牌。软 17 要牌"""
    return not (hard >= 17 or (ace and 18 <= hard + 10 <= 21))

def settle(cards, bet, dealer):
    """一手牌的返还。2 张牌 21 点为 2.5 倍（舍去小数），赢为 2 倍，平局为 1 倍"""
    mine, natural = best(*state(cards)), len(cards) == 2 and best(*state(cards)) == 21
    if mine > 21:
        return 0
    house = best(*state(dealer))
    if len(dealer) == 2 and house == 21:
        return bet if natural else 0
    if house > 21:
        house = 0
    if mine > house or (mine == house and natural):
        return bet * 5 // 2 if natural else bet * 2
    return bet if mine == house else 0

state 把手牌转换为“把 A 算作 1 的合计”和“是否有 A”，best 在可以把 1 张 A 算作 11 时返还这样算的合计（完整代码在文件里）。

洗牌被写成在“取那张牌时”才做该位置的交换。位置 n 在轮到自己交换之后就再也不会移动，所以结果与先全部洗完再取牌相同。随机数用的是 Python 的方式，所以出牌顺序不会和游戏一致，但洗法和规则相同。

take 和 settle 都没有接收之前各局结果、时间或下注者的地方。传进去的只有随机数来源和这一局的牌。

基本策略也在同一个程序里计算。把牌堆视为“每种点数始终以 13 分之 1 的概率出现”，对每种手牌比较停牌、要牌、加倍、分牌的平均结果，选出最好的。上面的表就是它的输出。

扑克（德州扑克）

  • 52 张牌堆为 1 副。每手牌重新生成
  • 5 / 10盲注。没有前注
  • 100～1,000可以带上桌的 Scrap
  1. 生成牌堆瞬间重新排好 52 张并洗牌
  2. 盲注和底牌自动下 5 和 10 的盲注，每人发 2 张
  3. 4 轮下注每人 30 秒中间依次发翻牌 3 张、转牌、河牌
  4. 摊牌瞬间用 2 张底牌 + 5 张公共牌比牌型
  5. 赔付瞬间底池全额归赢家。8 秒后开始下一手
项目牌桌的规则
人数2 人起。牌桌有 2、3、4、6 座 4 种
盲注庄位的下一位下 5，再下一位下 10（2 人时由庄位下 5）。庄位每手牌向旁边移动一位
买入在座位的储物格放 100～1,000 Scrap。不足 10 时从下一手起被排除
最小加注10 及以上（不能小于上一次的加注幅度）

庄家抽成（抽水）没有

赔付代码按下注额从少到多的层级，依次把底池交给赢家，最后检查“底池应该已经空了”。不存在机台抽走任何东西的代码。下注的 Scrap 会全额回到某位玩家手里。

所以，扑克没有“相对于庄家的平均返还”。把桌上所有人的盈亏加起来，总是 0。能不能赢，只取决于你是否比对手打得好。

验证常见说法

“记住出过的牌，就能在有利时下大注”

不成立算牌只在用过的牌不回到牌堆、直接进入下一局的情况下才有效。这台机器每局都重新生成 520 张，所以记下的信息无法带到下一局。牌堆在下注前就已生成，因此也不可能先看到这一局的牌再下注。

“连输了好几把。机台在攒钱，差不多该赢了”

不成立机台既不记得赔出了多少，也不记得收进了多少。下注的 Scrap 在一局结束时消失，返还的部分是新生成的。局与局之间带过去的只有座位和玩家手上的 Scrap。

“下大注就会来烂牌”

没有关系在接受下注之前，牌堆就已经洗好了。洗牌和发牌的代码都没有查看下注金额或下注者的地方。

“庄家会看你的手牌改变要牌方式”

不会改变庄家是否要牌，只由庄家自己的点数合计决定。17 点及以上停牌，软 17 要牌。玩家的手牌和赌注都不会被用到。

“时间段或服务器人数会影响赢的概率”

不会改变随机数只在洗牌这 1 处使用，而且是操作系统的加密用随机数。时间和人数都不会传进去。

“用工具可以偷看庄家的暗牌”

没有发送一局进行中，服务器不会把暗牌的内容发给客户端。扑克中其他人的底牌也一样。无论怎样检查本地一侧，看不到本来就不存在的东西。

“保险就是保障，手牌好的时候应该买”

买了吃亏保险是与主注分开的另一笔下注，平均为 −7.9%。不会因为自己手牌的好坏而改变。

“输了就加倍再下，最后一定能赢”

平均不变每局的结果与之前各局无关，所以下注金额的顺序不会改变平均结果。上限是 500，所以即使从 5 开始，连输 7 局后，下一次的加倍（640）就已经下不了了。

“坐的座位不同，来的牌就不同”

只差 1 张牌的份量牌按座位编号顺序发出，而洗法有上面提到的 1 张牌的偏差。下一节会加以验证。差距并没有大到能左右胜负。

“扑克的牌桌会让大牌互相碰撞来制造气氛”

没有这样做只是把 52 张洗好再从上面发而已。不存在选择给谁发什么牌的代码。牌桌本身没有抽成，也就没有制造气氛的理由。

座位与洗法的偏差

不论庄位在哪里，牌总是从编号最小的座位开始发。洗法的偏差（第 1 张牌不会是梅花 A）会直接体现在这个座位上。

我们统计了 2 人玩扑克时，每个座位拿到梅花 A 的比例，共 100 万手。

  1. 先发牌的座位（这台机器的洗法）1.97%
  2. 后发牌的座位（这台机器的洗法）3.91%
  3. 两个座位（均匀洗牌时）3.85%

先发牌的座位拿到梅花 A 的次数只有一半。因为第 1 张绝不会是它，只能在第 2 张拿到。同样地，后发牌的座位有 1 个位置不会来梅花 K，公共牌则分别有 1 个位置不会来梅花 10、9、8。

那么这会影响胜负吗？几乎没有影响。

  • 扑克： 假设所有人都不弃牌、打到最后，模拟 100 万次，2 人时底池的分配看不出差别（49.97% 和 50.03%，误差 ±0.05）。6 人时，第一个座位为 16.57%，只比均分的 16.67% 低约 0.1 个百分点（误差 ±0.04）。
  • 21 点： 这是 520 张中的 1 张，所以影响更小。我们计算出 1 人入座时，庄家优势增加 0.09 个百分点。3 人入座时，编号最小的座位增加 0.15 个百分点，其他座位增加 0.03～0.04 个百分点。这些都只是计算出的数字，没有做 3 人入座的模拟。3 人的数字是用与本文程序不同的一次性程序得出的。

差距并没有大到可以说“这个座位赢不了”。我们只是把“读代码可知存在 1 张牌的偏差”作为事实记录下来。

尚不清楚的地方

  • 编号最小的座位在哪个位置。 我们没有确认牌桌上哪个座位是 0 号。
  • 牌型判定的内部实现。 比较牌型的部分交给了一个与常见公开评估器形式相同的组件。我们没有读到它的内部。
  • 3 人及以上的全下。 筹码较少的玩家全下并获胜时，边池是否按通常规则分配。读代码看，有些地方的分配方式可能与通常不同。我们没有实际玩来确认。
  • 庄家优势的精确数位。 约 0.8% 是自制程序得出的估算。计算是把牌堆视为无限的近似，模拟有 ±0.05～0.1 个百分点的误差。
  • 本文的适用范围。 2026-11-07 版本的 PC 版服务器，赌注上限为默认的 500 的情况。上限可以按服务器更改，规则也可能在今后的更新中改变。

调查方法

我们阅读了服务器本体的代码（21 点和扑克相关类的中间代码），并从数据文件中读取了机台和牌桌的设置值。没有启动服务器。牌堆张数、庄家的要牌方式、赔付倍率、下注范围、盲注和时间，全都是读到的值。

庄家优势、基本策略表和各座位的比例，是用我们把读到的规则重新写成的程序计算和模拟得出的。到拿到梅花 A 的比例为止，都可以由 card-games.py 得出。扑克的底池分配和 21 点 3 人时各座位的差异，是用另一个一次性程序得出的。

这些并不是在游戏里实际玩并统计的结果，而是对“代码就是这样写的”的确认。
